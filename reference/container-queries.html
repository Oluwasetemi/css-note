Quick reference

CSS container queries

Make a component respond to the space its parent gives it.

Return to the interactive lesson

Decision rule

Media query: the environment or page shell changed.

Container query: the component’s allocated space changed.

Golden rule

Queried descendants cannot determine the container dimension being measured. Containment breaks that feedback loop.

Basic pattern

.slot {
  container-type: inline-size;
}

@container (min-width: 30rem) {
  .card {
    grid-template-columns: auto 1fr;
  }
}

Named pattern

.slot {
  container: card-slot / inline-size;
}

@container card-slot (min-width: 30rem) {
  .card { /* spacious layout */ }
}

Choose a type

inline-size: query the logical inline axis; block size still follows content. Start here.

size: query both axes; both dimensions are size-contained. Use deliberately.

Breakpoint test

Choose the smallest container width where the spacious layout is comfortable. Avoid device labels and viewport-derived magic numbers.

Common mistakes

  • Putting container-type on the component and trying to query that same element.
  • Using size without providing a block size.
  • Querying the nearest container when a named outer container was intended.
  • Replacing every media query; page-level responsiveness still belongs to media queries.

Test before shipping

  1. Render the component narrow and wide.
  2. Place it in different parents at one viewport size.
  3. Test content growth and long text.
  4. Check vertical writing if supported.
